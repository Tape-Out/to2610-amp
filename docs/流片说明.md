# to2610-amp 流片说明

流片说明报告（docx）的功能描述、寄存器含义、板级连接、测试说明与局限从这里取，只写在这一处。

## 功能描述

非对称双核的 Linux 系统芯片，面向 ECOS 2610 班车。它是 `to2610-kvc` 那一颗（KianV 的 RV32IMA、Sv32 SoC）再加第二个 KianV 核：第一个核照旧跑 Linux，第二个核跑实时系统，两个核共用一条总线、同一片 SDRAM 与全部外设，经一页寄存器互相打招呼。第二个核没放开时，整颗与 `to2610-kvc` 一样，同一份镜像照样起得来。

核是上游的，子模块不动。本仓自己写的有三样：`patch/amp.patch` 在黑盒仓拼好的源码（`to2610-kvc` 的那一颗）上例化第二个核与它的 CLINT、接进仲裁与核间那一页（两百来行）；`hwsrc/amp_arb.v` 是总线仲裁；`hwsrc/amp_ctl.v` 是核间的那一页。

### 功能一览

| 项 | 支持 | 说明 |
|:--:|:--:|:--:|
| 第一个核 | 同 `to2610-kvc` | RV32IMA、Sv32，跑 Linux；PLIC 的外部中断只进它 |
| 第二个核 | KianV，RV32IMA | 复位地址 `0x2000_0000`（Flash 起始处），只在机器态跑实时系统；有自己的 CLINT，机器态外部中断接门铃 |
| 存储与外设 | 同 `to2610-kvc` | 片外 SDRAM 32 MiB 与 SPI Flash，串口 0、SD 卡口、SPI 网卡口、1 位 GPIO；两个核都看得见，SDRAM 顶上的 1 MiB 约定归第二个核 |
| 总线 | 一条，两个核共用 | 一次访问做完才换人，换人之前空三拍；两边都在要就一人一次轮着来 |
| 核间 | 一页寄存器：两个方向各 8 位门铃、各一个字 | 给第一个核的门铃进 PLIC 的 26 号 |
| 第二个核的起停 | 核间那一页的 `RUN` | 复位后不动；收回时等它手上那次访问做完 |

### 两个核怎么起

复位后只有第一个核在跑，启动流程同 `to2610-kvc`：从 Flash 的 `0x2010_0000` 就地执行引导程序，把载荷搬进 SDRAM 再跳过去。Flash 的头 1 MiB 原本空着，这一颗把它留给第二个核的镜像。

往 `0x4004_0004` 写 1 放开第二个核，它从 `0x2000_0000` 起就地执行。从 Flash 取一条指令要一百多拍，跑不动节拍中断，所以镜像开头是一小段搬运：把整个镜像搬到 SDRAM 顶上的 `0x81F0_0000` 再跳过去（`htest/rtos/start.S` 是现成的样子）。Linux 的设备树里把这 1 MiB 从内存里划出去。

两个核各说各的话：第一个核用串口 0；第二个核没有串口，要说的字写进 `MSG_A`、拉 `BELL_A`，第一个核在 26 号中断里读走、写 `ACK_A` 清门铃。反方向用 `MSG_B`、`BELL_B`、`ACK_B`。

## 寄存器

`to2610-kvc` 的地址图原样保留（见它的流片说明）。这一颗新加的：

| 地址 | 含义 |
|:--:|:--:|
| `0x0300_0000` | 第二个核的 `msip` |
| `0x0300_4000` | 第二个核的 `mtimecmp`，64 位，低字在前 |
| `0x0300_BFF8` | `mtime`，只读，与 `0x0200_BFF8` 是同一个计数，每微秒走一格 |
| `0x4004_0000` | 核间那一页的标识，只读，`0x414D5031`（"AMP1"） |
| `0x4004_0004` | `RUN`：第 0 位放开第二个核，复位为 0 |
| `0x4004_0008` | `BELL_A`：写 1 的位置起，读回挂着的；挂着就经 PLIC 的 26 号报给第一个核 |
| `0x4004_000C` | `ACK_A`：写 1 的位把 `BELL_A` 清掉 |
| `0x4004_0010` | `BELL_B`：同上，挂着就是第二个核的机器态外部中断 |
| `0x4004_0014` | `ACK_B`：写 1 的位把 `BELL_B` 清掉 |
| `0x4004_0018` | `MSG_A`：一个字，约定由第二个核写给第一个核 |
| `0x4004_001C` | `MSG_B`：一个字，约定由第一个核写给第二个核 |

这一页两个核都能读写，谁写哪个字只是约定，硬件不拦。

## 板级连接

引脚与 `to2610-kvc` 逐位相同，kvc、amp、smp 三颗用同一块底板：payload 的 0 到 53 位（串口 0、Flash、SDRAM、SD 卡口、SPI 网卡口、1 位 GPIO），接法见 `to2610-kvc` 的流片说明。payload 第 n 位是 MPC-Frame 的 `user_io[n + 7]`；逐位的完整位表在报告的「payload 位表」里。

- 时钟 50 MHz，两个核同一个时钟。
- 串口 0 归第一个核，115200。第二个核没有自己的串口，要说话经核间那一页由第一个核转。
- Flash 里放三样：`0x0000_0000` 起是第二个核的镜像，`0x0010_0000` 是引导程序，其后是第一个核的载荷。
- 复位：按住复位时全部 payload 脚高阻，烧录器夹上 Flash 就能在板写。

## 测试说明

测试台 `tb.cpp` 来自黑盒仓，跑在 Verilator 上，带 SDRAM、Flash、串口的引脚级模型；被测的是 `ran asic` 出的那份交付文件。

| 用例 | 测什么 |
|:--:|:--:|
| hello、periph、isa、arch-test、boot | `to2610-kvc` 的五段原样再跑：第二个核没放开时，原有的通路与核的行为不许变 |
| amp：放开之前 | 核间那一页认得出来，`RUN` 是 0，门铃没人拉 |
| amp：第二个核起步 | 放开后它逐站报到（在 Flash 里起步、搬进 SDRAM、调度器起来之前、收的任务跑起来、发的任务等到头三个节拍），第一个核替它从串口说出来。调度器起来之前吃到的陷入也报原因与地址 |
| amp：FreeRTOS | 第二个核上三个任务：一个按节拍往队列里发 1 到 5，一个收了经 `MSG_A` 与门铃报给第一个核，一个最低优先级的不让出。五个数逐个经 26 号中断到第一个核，顺序与数都对：第二个核的计时器中断、`ecall` 让出、抢占、两个核共用总线都在里面 |
| amp：两个方向 | 最后一句是第一个核事先写进 `MSG_B` 的数加上五个数的和 |
| amp：收回 | `RUN` 写 0 之后门铃不再响 |

## 局限

- 同 `to2610-kvc` 的各条：缓存旁路、主频固定 50 MHz、没有 JTAG。
- 两个核轮着用一条总线，都在忙时各自比单核慢一半上下。
- 两个核的 `mhartid` 都是 0，原子指令只在各自的核里成立：两个核不能靠 LR、SC 或 AMO 抢同一把锁，共享的数据要靠门铃与约定来分。要对称的双核见 `to2610-smp`。
- 存储没有隔离：第二个核写得到 Linux 的内存，SDRAM 顶上那 1 MiB 归谁只是约定。
- 第二个核没有自己的串口与 PLIC 上下文，只有 CLINT 与一根门铃中断。
- Linux 与第二个核同时跑还没有在这一颗上验过，目前验到第一个核跑裸机、第二个核跑 FreeRTOS。
